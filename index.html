Why Fleetpad

A lot of projects.
One machine to run them on.

Fleetpad is for the Mac that already has the repos. It starts their dev servers, shows what each one is using, and clears the caches they leave behind.

  • Every repo, one grid

    Point Fleetpad at a folder of projects. Each card shows the script, the framework, and whether it is running — start and stop from there.

  • The process, with its log

    Port, uptime, CPU, memory, and the live output sit on the same row. A taken port shows up there, not in a terminal you already closed.

  • Which project is the machine

    CPU and resident memory are measured per project's process tree, so a dev server that keeps climbing is a row you can restart.

  • Cache you can delete on purpose

    node_modules, .next, target, dist, .turbo, and out, sized per project. A server that is still running stays locked.

One window

Run the fleet. Watch it. Clean up after it.

Stop bouncing between a terminal per repo, Activity Monitor, and a folder full of old node_modules.

RunningCacheCPUMemory

01Running

See what's actually up.
Logs included.

Every dev server in the fleet, with port, uptime, CPU, and memory. Open the live log, restart one project, or stop them all.

  • The log, live

    Follow the process output, copy it, or open the project folder. The tail stays on the row you selected.

  • Ports called out

    If a port is already taken, the row says so before you spend a minute wondering why start failed.

  • Recently stopped

    Projects you stopped stay in a short list, with Start one click away.

02Cache

See what the caches weigh.
Delete only what you pick.

node_modules, .next, target, dist, .turbo, and out — totaled across the workspace, then broken down per project.

  • Stale projects, grouped

    Projects that have not changed in 30 days are called out, with the disk they still hold.

  • Running stays locked

    A live dev server is not eligible for cleanup. Removing node_modules under it would break the process.

  • Clean the selection

    Check the projects and the cache kinds you want gone. The bar shows how much that frees before you confirm.

03CPU

Which project is the machine.
Sampled on this Mac.

A chart of CPU for the whole fleet, and a sparkline for each project's process tree, sampled every couple of seconds.

  • Now, average, and peak

    Switch the window between 1, 5, and 15 minutes, and sort by what's hot right now or by the peak.

  • Share of the machine

    Each row shows its slice of total CPU, next to the raw percent, so one busy project is obvious.

  • The process tree

    Numbers come from the project's own process tree, not a single PID that missed the workers.

Memory

Resident memory,
per project.

RSS for each process tree, how it moved in the last 10 minutes, and what else is using the Mac. A server that keeps climbing is marked, with Restart on the row.

  • Change over 10 minutes, or since the project started.
  • This Mac, split into projects, Fleetpad, other apps, and free.
  • Restart from the card or the table when growth doesn't settle.

Projects

The grid you start from.

Every detected project shows its package manager, script, cache, and whether it is running.

  • Folders, then projects

    A workspace is a folder of repos. Pin the ones you live in, and filter to what's running.

  • DEV and PROD

    Each card starts the script you pick. Stop it from the same place, or open the site, the folder, or your IDE.

  • A terminal when you need one

    The dock along the bottom keeps a shell on the project you already have selected.
